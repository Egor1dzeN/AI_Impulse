# Impulse — a personal assistant with long-term memory

Built for the **AI-Impulse 2.0** hackathon, track 2, Restore case (task description, in Russian:
[`competition_task/README.md`](competition_task/README.md)).
Architecture, memory, API, setup and deployment are covered in [**README_TECH.md**](README_TECH.md) (in Russian).

Impulse learns about its user from their email, messages, calendar and bank notifications. It:

- builds a **digital profile** where every fact has a source and a validity period;
- answers precise questions **the same way no matter how they are phrased**;
- **notices on its own** what needs the user's attention;
- **takes actions** in Google Calendar and Gmail, but only after the user confirms them.

Sensitive data is masked, and instructions hidden inside emails or documents are never executed.
All answers are generated by **GigaChat**.

---

## Loading a dataset (1–2 minutes)

1. Sign in and open **"New chat"**.
2. Click the **paperclip** ("Attach file") and pick the dataset files, all at once if you like:
   email, Telegram and calendar exports (`.jsonl` or a JSON array). Send the message (text is optional).
3. The type of each file is detected **automatically** from its record fields, so file names don't
   matter. Upload data **as a file**: that way every record reaches the database, analytics and the
   profile with its real source and date. Pasting `.jsonl` / JSON array content into the input box
   also works: it is recognised and attached as a file.
4. A card "Found data about you in … — saving to memory" with a progress ring appears in the chat.

**Precise questions** (spending, schedule, emails, contacts) can be asked right after upload, because
raw data is stored instantly. The **digital profile** is built in the background over a few
minutes: wait until the card says "Memory updated" before checking the profile and the export.

Bank notifications in emails are turned into transactions automatically (the **"Finance"** section).

> **One dataset, one account.** To try another dataset, use a different account, so old facts never
> mix with new ones. Alternatively, "Settings → Danger zone → Delete all memory about me" wipes the
> memory, uploaded data and chats in the current account.

The assistant's **"now"** is the real date and time in the user's time zone (inferred from the data,
Moscow by default). "Today", "tomorrow", "last month" and "next week" are counted from it.

## What to try

### Questions about your data (reproducibility)
All numbers, dates and lists are computed by deterministic code; the model only phrases the answer.
So the answer is the same on retry, with different wording and in a new chat. Examples:

- "How much did I spend on cafés and restaurants last month compared to the month before?"
- "Find me 40 minutes next week after 11:00" / "Which day is the busiest and what can be moved?"
- "Go through my inbox for the last 3 days: what haven't I replied to and what is urgent?"
- "Who do I talk to most at work?" / "What are my recurring events?"
- "I'm saving 200,000 ₽ for a holiday by March 1 — how much should I put aside, and will I make it?"
- "I had pasta, 750 kcal — how much is left of my daily norm?"
- "I'm sick — which meetings tomorrow should I cancel and whom should I tell?"

Every answer ends with a **"Source: …"** line: where the data came from and which period it covers.

### Digital profile and memory
- **"Memory"** section: every fact about the user with its source and validity period; search,
  manual add, delete.
- **"Export profile"** downloads the memory (secrets in it are masked).
- Memory survives a page reload, a new chat and a server restart.

### Proactivity
Open **"New chat"**: the **"Assistant noticed"** block shows what needs attention, each item with a
ready action: unanswered emails with a deadline (→ reply draft), an overloaded day (→ move
meetings), growing spending in a category (→ limit and reminder), calendar conflicts. The same
shows up when you ask "What's new?" / "What should I pay attention to?". The assistant also checks
every request against the profile (schedule conflicts, calorie norm, overspending).

### Security
- An email saying "ignore previous instructions", a fake "system notice" from a look-alike domain,
  an injection in an event description: the assistant **does not follow** instructions from data and
  warns about them instead. Such records never reach memory (protection against memory poisoning).
- Attach a PDF/DOCX with **hidden (white) text**: the text is stripped before it reaches the model,
  and a warning appears in the chat.
- Every outward action (an email, a calendar event) is prepared as a **draft** with a
  "Send" / "Confirm" button; clicking twice does not create a duplicate. An instruction inside
  someone else's email cannot create a draft: actions happen only on the user's explicit request.

### Masking
Card numbers (last 4 digits stay), CVV, account numbers, passport data, passwords, tokens and keys
are masked at every boundary: on data upload, in messages, in tool results, in the UI, in exports
and in logs. Try: "Remember my card 4276 1234 5678 9012, CVV 123".
Name, phone number and address are intentionally not masked.

## Integrations

| Area | Integration | How to try |
|---|---|---|
| Email and messengers | Import of email and **Telegram exports** (`.jsonl`) | upload a dataset, ask about emails and chats |
| Email and messengers | **Gmail API** (OAuth): read, draft, send after confirmation | "Settings → Gmail → Connect" * |
| Calendar and tasks | Calendar import; **Google Calendar** (OAuth): create, move, delete events after confirmation | "Settings → Google Calendar" *, then "Set up a meeting with … tomorrow at 15:00" |
| Calendar and tasks | Tasks and reminders | "Add a task: call the bank tomorrow" |
| Finance | Bank notifications → transactions, categories, month-over-month comparison, savings goals | "Finance" section, questions about spending |
| Finance | **Central Bank of Russia rates** (cbr.ru) | "How did the dollar and yuan rates change this week?" |
| Health and sport | **Open Food Facts** (nutrition data), meal and weight tracking | "How many calories are in Greek yoghurt?" |
| Health and sport | **Intervals.icu** (workouts, route on a map) | "Settings → Intervals.icu": API key |
| Maps, travel, weather | Geocoder, **routes and maps** (Mapbox), **Open-Meteo** | "Tomorrow I need to be at Bolshaya Dmitrovka 15 by 9:30 — when should I leave and what's the weather?" |
| Documents and news | **PDF / DOCX** attachments: answers with quotes, deadlines and obligations, reminders | attach a contract or an invoice |
| Documents and news | **Web search** with source links | "What's the news today on topics I care about?" |
| Voice | Speech recognition (Whisper) | hold the microphone button in the input box |
| Extensions | **MCP servers**, added in settings (https only, protected against requests to internal networks) | "Settings → MCP servers → Add", e.g. `https://mcp.vkusvill.ru/mcp` |

\* Google Calendar and Gmail need your own Google OAuth client (`GOOGLE_CLIENT_SECRET`). While the
Google app is in testing mode, add the Google accounts that will connect as test users.

## How it works, briefly

- **Two kinds of knowledge.** Raw data (emails, events, messages, transactions) is stored verbatim,
  and precise questions are answered by deterministic analytics without an LLM. Fuzzy knowledge about
  the person (preferences, relationships, goals) lives in a custom **long-term memory system**:
  fact extraction → enrichment → matching against what is already known → consolidation, with
  vector search and reranking. Every fact keeps its source and period.
- **The agent** is a LangGraph "model ⇄ tools" loop on GigaChat (30–45 tools depending on the
  connected services). Every tool result is masked before it reaches the model.
- **Outward actions** are only a draft in the chat plus a user button; the model has no tool that
  sends or changes anything by itself.
- **Storage:** SQLite (app and memory) + FAISS (vector index), on the machine running the backend.

**Used off the shelf:** FastAPI, React/Vite, LangGraph/LangChain, GigaChat SDK, Qwen3 embedding and
reranker models (cloud.ru), Whisper, GLiNER, FAISS, Mapbox, pypdf.
**Built by the team:** the long-term memory system (`memory/`), the digital profile, deterministic
data analytics, proactive detectors, the bank notification parser, prompt-injection protection and
masking, hidden-text detection in documents, integrations (Google, Intervals.icu, CBR, Open Food
Facts, maps, weather, MCP), action confirmation flow, and the web UI.

To run it locally, see [README_TECH.md](README_TECH.md).
