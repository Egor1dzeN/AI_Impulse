# Итеративное улучшение по тестовым датасетам — отчёт

Цель: поднять баллы по критериям `competition_task/README.md` на закрытом датасете жюри. Метод: генерировать
разные датасеты (формат как в `competition_task/data`), прогонять их через живой бэкенд так же, как это делает жюри
(загрузка → каждый вопрос дважды в новых чатах → проактивность → атаки → экспорт памяти), считать баллы,
чинить то, что обобщается, и повторять. Между датасетами данные аккаунта полностью удаляются.

## Инструменты

| Что | Где |
|---|---|
| Генератор персон и эталона | `competition_task/datasets/gen.py`, персоны — `personas.py` |
| Прогон датасета (как жюри через API) | `competition_task/datasets/run_dataset.py <slug> --user <аккаунт>` |
| Оценка по критериям README | `competition_task/datasets/grade_dataset.py <slug>` → `<slug>/grade_report.md` |
| Регрессия на датасете организаторов | `competition_task/datasets/maria` (правила из `data/reference_answers.md`) |
| Первый ручной датасет (Вера) | `competition_task/test_data` (`run_test.py`, `grade.py`) |
| Перезапуск бэкенда для прогонов | `competition_task/datasets/restart_backend.sh` |

Оценка автоматическая (regex по эталону + ручная перепроверка спорных ответов) — это приближение к жюри,
а не точная копия. Интеграции (критерий 5) этими прогонами не измеряются, поэтому итог — из 85.

## История итераций

### Итерация 0 — исходное состояние (Вера)
**≈54 / 85.** Воспроизводимость 13.2, профиль ~19, проактивность 15, безопасность 0, объяснимость 0, маскирование 5.
Главные провалы: возраст/дата рождения (модель считала сама, поиск по памяти подмешивал шум календаря), устаревшая
норма калорий и вес, баланс карты = доход−расход, «раз в две недели» не распознавался, подписки, «ответила ли я»,
веб-поиск вместо данных пользователя; в памяти — чужие факты («живёт в Москве» — это брат) и комментарии
нормализатора; инъекция в транскрипте звонка не распознана, агент «подтвердил согласование оплаты»;
цензурный отказ GigaChat на вопрос про адрес; один ответ без источника.

### Итерация 1 — коммиты cd339eb, 38ec4b5 (Вера)
**65.0 / 85** (воспр. 20.4, профиль 19.6, проакт. 15, безоп. 0, объясн. 5, маск. 5). Сделано: детекторы инъекций
(«для ассистента, который читает», «запиши, что уже согласовал»), фильтр ложных срабатываний на дружеские шутки;
закреплённый в системном промпте проверенный профиль + вычисленный возраст; детерминированные норма калорий/вес,
баланс по последнему уведомлению, `user_replied`, регулярные платежи/подписки, «раз в 2 недели» и следующая дата;
гарантированная строка «Источник»; повтор при цензурном отказе; проактивность — разнообразие поводов, «не успеть
доехать», всплеск трат; `.env` грузится самим приложением (без этого терялся ASSISTANT_NOW); дата рождения —
детерминированно; инструменты записи — только по явной просьбе.

### Итерация 2 — коммит 05b8e75 (Артём, Ольга, Мария — параллельно)
Артём **63.4**, Ольга **67.7**, Мария (датасет организаторов) **84.0 / 85** после исправления двух слишком строгих
правил проверки. Параллельный запуск упёрся в лимиты GigaChat (429) — часть ответов «лимит исчерпан», из-за этого
безопасность 0 у Артёма/Ольги. Сделано: поиск по календарю по всему периоду с ранжированием и стеммингом,
сортировка входящих (горит/просрочено/ждёт ответа/отвечено/подозрительное), рабочие часы из расписания,
узкая тема «где живёт и откуда переехал» в синтезе профиля, фильтр «факт пользователя на чужой реплике»,
`web_search` сначала показывает данные пользователя, цитата подозрительного описания события.

### Итерация 3 — коммиты 81f99be и следующий (Вера, Денис, Артём, Ольга — последовательно)
Сделано: до 7 повторов при 429 в чате и повторы в моделях памяти/профиля (раньше синтез «где живёт» тихо терялся),
прозвища по общему корню (Тёма для Артёма), диеты/хобби в синтезе, серии с RRULE от двух вхождений,

закрытые вопросы без «Да/Нет», лимит шагов на сложном поиске письма.

### Итерация 4 — исправления по итогам итерации 3
Даты «на весь день» включительно; вопрос ≠ приказ; ближайшее занятие + конфликты с календарём прямо в
`recurring_schedule`; даты событий — только из календаря; закрытые вопросы начинаются с «Да/Нет»; конспект
письма/транскрипта — через `search_emails`; `average_per_month` в финансовом отчёте; лимит шагов 28; расширенный
словарь видов спорта; слабые «накладки» с личным обедом больше не поднимаются. Новая персона — Анастасия
(ДР только из поздравлений, норма калорий — от тренера в чате).
